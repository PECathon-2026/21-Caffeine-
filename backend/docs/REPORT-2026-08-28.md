## Wave 4 — adversarial review

The review ran four dimensions (memory/resource leaks, latency vs the 10 ms
budget, correctness, safety invariants) with independent finders whose
findings were then adversarially verified. **12 findings confirmed, 0
refuted**; all 12 are fixed in `e917236`, each with a regression test that
fails without its fix. The safety-dimension agent was blocked by a content
filter, so that dimension was audited by hand instead (three additional
fixes below).

### Confirmed and fixed

**Correctness (high):**
- Attempt-outcome writes had no lease guard: a worker whose lease had been
  reclaimed could clobber the new owner's running task and burn its retry
  budget. Terminal transitions are now single-statement CAS updates keyed on
  `(status='running', lease_owner)`; a stale worker gets `LeaseLost` and
  walks away.
- Reviewer/security gates recorded the coder's patch hash as read at the
  moment the reviewer finished — not the hash it actually reviewed. A coder
  retried mid-review could merge unreviewed code under a stale approval.
  Gates now bind the dependency hashes snapshotted when the review attempt
  starts; a mid-review retry fail-safes into re-review.

**Correctness (medium/low):**
- `retry_task` left already-`ready` descendants ready, letting a dependent
  run concurrently with (or before) its retried dependency; the cascade now
  demotes them to `proposed` and readiness is re-derived.
- A cancel racing `run_mission`'s unguarded `running` write could downgrade
  a cancelled mission to `paused` (resumable). Mission transitions into
  `running`/`paused` are now guarded updates that lose gracefully.
- Rejecting a policy approval recorded the decision but never released the
  parked task, stranding it (and the mission) in `blocked` forever. Reject
  now releases parked tasks exactly like approve; the policy decider
  surfaces the denial and consumes an attempt.
- SSE reconnects: `Last-Event-ID` now takes precedence over `?after=`, so a
  standard EventSource reconnect no longer re-replays the whole backlog.

**Leaks / resources:**
- (high) The circuit breaker's half-open probe permit leaked if the probe
  request was cancelled (mission pause/cancel mid-probe), permanently
  disabling that provider until daemon restart. The probe now settles on
  cancellation in both request and stream paths, including a `Drop` settle
  for streams dropped mid-flight.
- A stalled SSE client (e.g. a SIGSTOPped TUI) could park its feeder on a
  full channel where the shutdown token was never polled, hanging graceful
  shutdown forever while holding the workspace lock. Every feeder send now
  races the shutdown token.
- The daemon's diff cache grew one full unified diff per mission forever;
  it is now an 8-entry LRU.
- Worktrees and branches of cancelled/failed missions were never reclaimed
  (one repo-sized checkout per coder task, forever). Cleanup now runs when
  a worker exits with the mission terminal, inline on cancel when no worker
  is live, and on vacuous completion (mission ends with nothing integrated).
  Blocked/paused missions keep their checkouts — they can resume.

**Latency:**
- The TUI Diff tab cloned the entire unified diff string every frame; it
  now renders a zero-copy window over a cached line index.
- `expire_overdue` full-scanned the approvals table on every approval op
  (its doc claimed "indexed"); a v3 partial index now serves it, and
  `pending_approvals` was split into two cached statements so the existing
  mission/status index is usable.

### Safety audit (manual)

Verified holding: read-only roles are hard-blocked from writes at both the
registry and the write-guard layer; `.env*` denial is pre-rule and survives
allow-everything configs; the sandbox fails closed in `required` mode,
clears the environment, masks `.env*` with `/dev/null`, and binds no home
directory; delegation depth/count caps are enforced; off-loopback binds
without a token are refused at boot; approvals cannot be decided through
any model-reachable tool.

Three gaps found and fixed:
- **Scope verification could be blinded by rename detection**: `git diff
  --name-only` reports only the new path of a rename (empirically
  confirmed), so an out-of-scope deletion pairing with an in-scope addition
  passed the check. Diffs now run `--no-renames`.
- **In-workspace symlinks could alias denied paths**: policy and scope
  checks evaluated the requested path string, so a pre-existing symlink
  (`src/settings → .env`) read secrets under a clean name. Checks now
  evaluate the symlink-resolved workspace-relative path.
- Bearer-token comparison in the daemon auth layer is now constant-time.

workstation's existing Claude Code and Codex credentials: planner, reviewer
and security on `claude-fable-5` (Anthropic wire, `x-api-key`), coder on

chat/completions.

### Real-work stress test: the portfolio-site mission

A second, much larger live mission — "build an interactive portfolio site
for the 23 projects in projects.json" (5 planned tasks + 1 delegated,
Claude planning/designing/reviewing, mixed coders) — was run to force the
orchestrator through dependency chains, delegation, retries, steering, and
budget limits. It shipped a working site (`~/Desktop/Projects/projects-site`,
~$8.70, 87 model calls) and exposed four architectural gaps plus one
transport bug, all fixed with regression tests in `68e0a2c`:

- **Deferred integration starved dependent coders.** Patches only merged at
  full queue-drain, so a coder needing another coder's file never saw it —
  the reviewer then (correctly) rejected the incomplete result. Gated
  patches now merge eagerly: before each spawn wave and before a mission
  blocks.
- **Stale worktrees on retry.** A retried task reused a worktree forked
  before its dependency merged. Worktrees are now recreated whenever the
  stored fork point no longer matches the integration head (or was never
  persisted); same-base retries still reuse.
- **Delegated coders had no reviewer**, making their patches permanently
  unmergeable under the gate rule. Delegating a coder now auto-creates a
  paired reviewer task.
- **Empty-diff retries kept stale patch hashes**, demanding gates for
  patches that no longer existed. The hash is now cleared.
- **Anthropic default max_tokens (4096) truncated write_file turns** —
  densely escaped JSON tokenizes near one token per character — surfacing
  as a cryptic "protocol violation". Default raised to 16384, and both
  transports now report token-cap truncation as a clear provider error.

Also validated live: `retry --model` reassigning a task across providers,
`steer` correcting a delegated task's stale premise, per-provider rate
pacing, cost/token ceilings halting the mission, and cancel reclaiming
every worktree and branch. One known gap remains: finalize refuses when
the user branch moved mid-mission ("rebase the mission first") and no
rebase operation exists yet — the mission branch had to be merged by hand.

## TUI: first human contact + the keelcode UX pass

Anay's first real TUI session hit an immediate bug: the TUI mints chat
session ids locally but never created them on the daemon, so the first
message bounced with "chat session not found". Fixed server-side — the
first message into a client-minted session now materializes it, titled
from its opening words (regression test in tests/daemon.rs).

Then a UX overhaul modeled on keelcode-cli (patterns extracted from the
actual repo):
- **Slash finder**: "/" opens a fuzzy autocomplete popup above the
  composer — descriptions, arg hints, wrapping ↑↓, window-edge markers,
  Tab completes, stays open on zero matches, and the keelcode Enter
  authorization rule (a fuzzy match is a suggestion, never an
  authorization).
- Arg ghost hints after completion; static first-run welcome screen;
  Ctrl+J newline / Ctrl+U / Ctrl+W in the composer; a permanent key bar
  in the status line.
- Verified live by driving the real binary through a pty: welcome,
  finder open, fuzzy filter, tab-complete + hint, no-match row, and
  /quit-via-finder all pass in an actual terminal.

Follow-ups worth doing next (from the keelcode study): unified finder
sources (@files ~sessions %models), queue-while-busy with inline edit,
mouse click-to-expand tool rows, transcript selection-copy, and the
progressive hint engine.

Two genuine bugs found only by the first live run, both fixed with
regression tests:
- **Auto-finalize failure destroyed merged work.** With `finalApproval =
  false`, a finalize refusal (dirty tree) propagated as an error, the worker
  marked the mission `failed`, and terminal cleanup deleted the mission
  branch holding the merged-but-unfinalized patch. Auto-finalize failures
  now block the mission (recoverable, matching the approval path), and
  failed missions keep their mission branch — only explicit cancels delete
  it.
- **`.maestro/` counted as dirt.** In a repo that never ran `maestro init`
  (so the state dir is not gitignored), the untracked `.maestro/` made
  `is_clean` false and finalize permanently impossible. The cleanliness
  check now ignores Maestro's own state directory.
